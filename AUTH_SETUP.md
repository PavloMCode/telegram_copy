# Пароль та підтвердження через Gmail

Реєстрація: телефон → ім’я, email, пароль → код з email → чати.
Повторний вхід: email і пароль → новий email-код → чати.
Старі локальні демонстраційні профілі не є серверними акаунтами: їх потрібно зареєструвати.
Номер телефону є контактним полем; SMS-перевірки немає.

## Сервер

Потрібні Java 17+, MongoDB і Gmail з дозволеним SMTP-доступом.
Для Gmail увімкніть двоетапну перевірку й створіть пароль застосунку:
[інструкція Google](https://support.google.com/mail/answer/185833?hl=en).
У деяких керованих Google Workspace акаунтах ця можливість недоступна.

У PowerShell встановіть змінні середовища тільки для процесу запуску:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:MONGODB_URI = 'mongodb://localhost:27017/messenger'
$env:SMTP_USERNAME = 'your-sender@gmail.com'
# Введення приховане; пароль не записується у команду або файл.
$env:SMTP_PASSWORD = Read-Host 'Gmail app password (without spaces)' -MaskInput
# Лише для локальної розробки через HTTP:
$env:SESSION_COOKIE_SECURE = 'false'
Set-Location C:\Study\MS\demo
.\mvnw.cmd spring-boot:run
```

Не використовуйте основний пароль Google і не додавайте секрети до Git.
Раніше URI MongoDB був записаний у конфігурації; поточна конфігурація читає його зі змінної середовища.
Якщо старі облікові дані ще діють, змініть їх: історія Git може містити попереднє значення.

Відсутність SMTP-параметрів, недоступність MongoDB або помилка надсилання
повертають помилку. Демонстраційного коду або обходу перевірки немає.

## Flutter

Android-емулятор використовує `http://10.0.2.2:8080` за замовчуванням.

```powershell
flutter run --dart-define=AUTH_API_URL=http://10.0.2.2:8080
```

Для iOS-симулятора в debug-режимі: `--dart-define=AUTH_API_URL=http://localhost:8080`.
Для фізичного пристрою та release-збірки використовуйте доступний пристрою HTTPS-сервер:

```powershell
flutter run --release --dart-define=AUTH_API_URL=https://your-api.example.com
```

На сервері production залиште `SESSION_COOKIE_SECURE=true` (типове значення)
і налаштуйте HTTPS. Не вмикайте CORS з довільними origin.
Поточний HTTP-клієнт призначений для Android/iOS, а не Flutter Web.

## Поведінка та обмеження

- Паролі довжиною 12–128 символів зберігаються як salted PBKDF2-хеші.
- Шестизначний випадковий код діє 5 хвилин, має максимум 5 спроб і використовується один раз.
- Повторне надсилання доступне через 60 секунд; новий challenge скасовує попередній.
- Ліміти запитів за email та IP зберігаються в MongoDB у 15-хвилинних часових вікнах.
- Email і телефон мають унікальні індекси; акаунт створюється після підтвердження email.
- Сесія створюється після перевірки коду. Її ідентифікатор змінюється після входу.
- Сесії живуть у пам’яті сервера й завершуються після 30 хвилин неактивності або перезапуску сервера.
- Клієнт тримає cookie лише в пам’яті. Перезапуск застосунку потребує нового входу.
- Вихід анулює серверну сесію й очищає локальну cookie. Якщо сервер недоступний,
  застосунок повідомить, що серверна сесія завершиться за тайм-аутом.
- Відновлення забутого пароля та зміна email ще не реалізовані.
- Наявні чати залишаються локальними; їхні серверні API не додавалися.

Тести використовують підмінений поштовий транспорт. Реальне надсилання через Gmail
потребує ваших параметрів SMTP і окремої перевірки доставки.

```powershell
flutter test
Set-Location demo
.\mvnw.cmd '-Dtest=AuthServiceTest,AuthMailSenderTest' test
```
